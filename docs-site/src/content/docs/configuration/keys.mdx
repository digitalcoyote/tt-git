Every key in tt-git can be changed in the `[keys]` tables of
[`config.toml`](/configuration/). For the full list of default keys, see
[Keyboard shortcuts](/reference/keys/).

## Contexts

Bindings belong to a context. Each pane has one, plus `global` for keys that
work everywhere:

| Context | Where it applies |
|---|---|
| `global` | Everywhere, unless the focused pane's context binds the same key. |
| `graph` | The graph pane. |
| `status` | The status pane. |
| `branches` | The branches pane, on every tab but Stash and Worktrees. |
| `stash` | The branches pane on its Stash tab. It doesn't fall back to `branches`. |
| `worktrees` | The branches pane on its Worktrees tab. It doesn't fall back to `branches`. |
| `details` | The details pane. |
| `stage` | The staging view, while you stage a file by hunk or line. |
| `blame` | [Blame](/panes/blame/), while the details pane blames a file. |

When you press a key, tt-git looks it up in the focused pane's context first,
then in `global`. That's why <kbd>a</kbd> means "all branches / current branch"
in the graph but "stage everything" in the status pane.

## Changing a binding

Name the context's table, then set a command to one key or a list of keys:

```toml title="config.toml"
[keys.global]
quit = ["q", "ctrl+c"]
palette = ":"

[keys.graph]
toggle_scope = "b"

[keys.branches]
checkout = ["enter", "o"]
```

The keys you set **replace** that command's default keys in that context.
In the example, `palette = ":"` removes the default <kbd>ctrl+p</kbd>. To keep a
default, list it too.

Changing a command in one context leaves the others alone. `[keys.graph]
new_branch = "N"` changes the key in the graph only; <kbd>n</kbd> still makes
a branch in the branches pane.

The help bar, the help popup (<kbd>?</kbd>) and the command palette all show
your keys, not the defaults.

<Aside type="caution">
A misspelled command name or a key tt-git can't read stops tt-git from
starting, with an error that names the table and command, for example
`keys.graph.toggle_scope: invalid key 'ctrl+'`.
</Aside>

## How to write keys

| Write | For |
|---|---|
| `q`, `Q`, `?`, `+`, `}` | A character. Uppercase means shift: `Q` and `shift+q` are the same key. |
| `ctrl+c`, `alt+enter`, `ctrl+alt+x` | Modifiers joined with `+`. `control` and `meta` work too. |
| `ctrl++` | <kbd>ctrl</kbd> with the <kbd>+</kbd> key. |
| `space`, `enter`, `esc`, `tab`, `shift+tab`, `backspace` | Named keys. `return`, `escape`, `backtab` also work. |
| `up`, `down`, `left`, `right` | Arrow keys. |
| `home`, `end`, `pageup`, `pagedown` | Also `pgup`, `pgdn`. |
| `delete`, `insert` | Also `del`, `ins`. |
| `f1` … `f24` | Function keys. |

Names aren't case-sensitive, except single characters.

## Binding plugin actions

To run a [plugin action](/plugins/manifest/#actions) with a key, add a
`[[keys.command]]` entry:

```toml title="config.toml"
[[keys.command]]
key = "ctrl+o"
type = "plugin_action"
command = "acme.github.open-commit"   # the action's qualified id
description = "open on GitHub"        # optional
context = "graph"                     # optional; default: everywhere
```

| Field | |
|---|---|
| `key` | The key, written as above. |
| `type` | Always `plugin_action`. |
| `command` | The qualified action id: the plugin's id, a dot, and the action's id. `tt-git plugin action list` prints them. |
| `description` | Optional. |
| `context` | Optional. One of the contexts above; the default is `global`, so the key works in every pane. |

Plugin bindings are checked before the built-in ones, and a binding for the
focused pane's context wins over a `global` one. The command palette shows the
key next to the action.

## Keys you can't rebind

A few keys belong to dialogs and lists rather than to a pane, and are fixed:

- In dialogs and prompts: <kbd>enter</kbd> confirms, <kbd>esc</kbd> cancels,
  <kbd>tab</kbd> switches options (worktree, what to stash), <kbd>ctrl+u</kbd>
  clears the text, and <kbd>y</kbd>/<kbd>n</kbd> answer a yes/no question.
- In the palette and pickers: <kbd>up</kbd>/<kbd>down</kbd> or
  <kbd>ctrl+p</kbd>/<kbd>ctrl+n</kbd> move.
- In the help popup: type to search, <kbd>backspace</kbd> and
  <kbd>ctrl+u</kbd> edit the search, <kbd>esc</kbd> closes.
- While you type a filter or a blame search: <kbd>backspace</kbd> deletes,
  <kbd>enter</kbd> keeps it and <kbd>esc</kbd> drops it.
- In plugin panes, the keys in `[plugins] pane_release_keys` (default
  <kbd>ctrl+\\</kbd> and <kbd>f12</kbd>); every other key goes to the plugin.
